# 3. 콘텐츠(DB) 스키마

목적: 게임 목록과 좋아요 데이터가 어디에, 어떤 모양으로 저장되는지 정한다.

| 데이터 | 저장 위치 | 누가 쓰나 | 누가 읽나 |
|---|---|---|---|
| 게임 파일 | 저장소 `play/{ID}.html` | 동기화 스크립트 | 방문자(게임 주소) |
| 게임 목록 | 저장소 `site/games.json` | 동기화 스크립트 | 갤러리 화면 |
| 교사 수정값 | 저장소 `overrides.json` | 교사(손으로) | 동기화 스크립트 |
| 좋아요 | Firestore `likes` | 학교 계정 학생 | 갤러리 화면 |
| 접속 설정 | 저장소 `site/config.js` | 최초 1회 설정 | 갤러리 화면 |

## 1. `site/games.json`

```json
{
  "updatedAt": "2026-11-24T01:20:00.000Z",
  "games": [
    {
      "id": "3115",
      "studentNo": "3115",
      "name": "전예찬",
      "title": "🎱 클래식 8-BALL 포켓볼 — PRO TOURNAMENT",
      "file": "3115.html",
      "driveId": "1bEUJn1mFSnXKaHq4s3TLKrwCRNHOfxHw",
      "sourceName": "8_ball - 3115전예찬.html",
      "hash": "sha256 앞 16자",
      "size": 136663,
      "addedAt": "2026-11-24T01:20:00.000Z",
      "updatedAt": "2026-11-24T01:20:00.000Z"
    }
  ],
  "skipped": [
    {
      "sourceName": "주술회전 철권 스타일 대전 게임 제작 - Google Gemini - 3109오예준.html",
      "driveId": "1wZTLcVTa_euSvOI2m_wn4h4OyoawnJBo",
      "reason": "AI 대화 화면 저장본 (게임 파일 아님)"
    }
  ]
}
```

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | `^\d{4}(-\d+)?$` | 게임 ID. 좋아요의 기준 키. 불변 |
| `studentNo` | 4자리 문자열 | 학번 |
| `name` | 문자열 | 이름 (공백 제거) |
| `title` | 문자열 ≤ 60자 | 게임 제목 |
| `file` | `{id}.html` | 게임 주소 기준 상대 경로 |
| `driveId` | 문자열 | 드라이브 파일 ID. 다시 제출·두 번째 작품 판단에 사용 |
| `sourceName` | 문자열 | 원래 파일명 (문제 추적용) |
| `hash` | 문자열 | 내용 변경 감지 |
| `addedAt` | ISO 시각 | 갤러리에 처음 올라온 때. NEW·최신순 기준 |
| `updatedAt` | ISO 시각 | 내용이 마지막으로 바뀐 때 |

`games` 는 학번 오름차순으로 저장한다 (커밋 변경 내역을 읽기 쉽게).

> **개정 (2026-11-24)** — 위 예시의 `skipped` 는 `site/games.json` 에서 빠지고 저장소 루트의 `sync-report.json` 으로 옮겼다(원래 파일명 전체는 사이트에 내보내지 않는다).
> 대신 갤러리의 "다시 제출이 필요해요" 안내에 쓰는 `rejected` 가 추가됐다.
>
> ```json
> "rejected": [
>   { "who": "3109 오예준", "reason": "AI 대화 화면 저장본 (게임 파일 아님)", "fix": "AI와 대화한 화면을 저장한 파일이에요. …" }
> ]
> ```
>
> | 필드 | 설명 |
> |---|---|
> | `who` | 학번·이름을 읽을 수 있으면 `학번 이름`, 못 읽으면 올린 파일 이름 |
> | `reason` | 올라가지 않은 이유 |
> | `fix` | 학생이 할 일 |
>
> 교사가 `overrides.json` 으로 숨긴 게임은 `rejected` 에 넣지 않는다. 학생이 고쳐서 다시 올리면 다음 동기화 때 목록에서 자동으로 빠진다.

## 2. `overrides.json` (교사가 직접 편집, 없어도 됨)

```json
{
  "3105": { "title": "무궁화 꽃이 피었습니다" },
  "3113": { "hide": true }
}
```

| 키 | 효과 |
|---|---|
| `title` | 제목을 이 값으로 바꿈 |
| `hide` | `true` 면 갤러리와 게임 주소에서 모두 내림 (좋아요 기록은 유지) |

키는 게임 ID다.

## 3. Firestore

### 컬렉션 `likes`

문서 ID: `{gameId}_{uid}` 예) `3115_Xk2aB…`

| 필드 | 형식 | 설명 |
|---|---|---|
| `gameId` | 문자열 | 게임 ID |
| `uid` | 문자열 | Firebase 사용자 uid |
| `createdAt` | 서버 시각 | 누른 때 |

- 이메일·이름은 **저장하지 않는다**. 읽기가 공개이므로 개인정보를 넣지 않는다.
- 사용하는 조회:

| 용도 | 조회 | 비용 |
|---|---|---|
| 게임별 좋아요 수 | `where gameId == X` 의 `count()` | 게임당 읽기 1회 (1,000개까지) |
| 내가 누른 게임 | `where uid == 나` | 내 좋아요 수만큼 |

- 두 조회 모두 단일 필드 색인으로 충분하다 (복합 색인 불필요).
- 예상 사용량: 게임 30개 × 방문 1회 = 읽기 약 30~60회. 하루 500회 방문해도 무료 한도(읽기 5만/일) 안이다.

### 보안 규칙 (`firestore.rules`)

`01_핵심로직_규칙명세서.md` 3.4 표를 그대로 구현한다.

## 4. `site/config.js`

```js
window.APP_CONFIG = {
  allowedDomain: "dongshin.ms.kr",
  playBase: "https://<게임 주소>/",      // 끝에 / 포함
  firebase: { apiKey: "...", authDomain: "...", projectId: "...", appId: "..." }
};
```

Firebase 웹 설정값은 공개되어도 되는 값이다 (접근 통제는 보안 규칙이 한다).

## 5. 보관·삭제

| 상황 | 처리 |
|---|---|
| 게임이 폴더에서 삭제됨 | `play/` 파일과 목록에서 제거. `likes` 문서는 남김 |
| 학년도 종료 | Firebase 콘솔에서 `likes` 컬렉션 삭제, 새 드라이브 폴더 ID로 교체 |
