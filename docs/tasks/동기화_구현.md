# 작업 지시서 — 동기화 스크립트 `scripts/sync.mjs`

## 목표
구글 드라이브 공개 폴더의 학생 HTML 게임을 저장소로 가져와 `play/{id}.html` 과 `site/games.json` 을 갱신하는 Node.js 스크립트.
Node 20 이상, **외부 패키지 없음**(내장 `fetch`, `node:fs/promises`, `node:path`, `node:crypto`, `node:url` 만). ESM.
출력은 **`scripts/sync.mjs` 파일 내용 전체만**. 설명 문장 금지.

## 경로 (스크립트 위치 기준 저장소 루트 = `scripts/..`)
- `sync.config.json` : `{ "folderIds": ["드라이브 폴더 ID", ...] }`
- `overrides.json` : 없을 수 있음. `{ "3105": { "title": "…", "hide": true } }`
- `inbox/` : 없을 수 있음. 여기에 있는 `*.html` 은 드라이브 파일과 똑같이 취급 (driveId = `"local:" + 파일명`, 내용은 파일에서 읽음)
- `site/games.json` : 이전 결과(없으면 `{games:[]}`)이자 출력
- `play/` : 게임 파일 출력

## 1단계 — 목록 가져오기
폴더 ID 마다 `https://drive.google.com/embeddedfolderview?id={ID}` 를 GET (헤더 `Accept-Language: ko`, `User-Agent: Mozilla/5.0`).
응답 HTML 에서 항목을 뽑는다. 각 항목은 이런 모양이다:
```html
<div class="flip-entry" id="entry-1bEUJn1mFSnXKaHq4s3TLKrwCRNHOfxHw" ...> ... <div class="flip-entry-title">8_ball - 3115전예찬.html</div> ...
```
- 정규식 예: `/id="entry-([\w-]+)"[\s\S]*?class="flip-entry-title">([^<]*)</g`
- 제목의 HTML 엔티티(`&amp; &lt; &gt; &quot; &#39; &#숫자;`)를 풀 것.
- 이름이 `.html` 로 끝나는 것만 (대소문자 무시).
- **안전장치**: HTTP 오류이거나, 어떤 폴더에서든 `flip-entry` 가 하나도 없으면 "목록을 읽지 못했습니다" 를 출력하고 `process.exit(1)`. 이때 어떤 파일도 쓰거나 지우지 않는다. (단, 페이지에 항목은 있는데 html 이 0개인 경우와 inbox 만 쓰는 경우(folderIds 가 빈 배열)는 정상 진행)

## 2단계 — 내려받기
`https://drive.google.com/uc?export=download&id={driveId}` (redirect follow). 동시에 4개까지.
- 응답이 200 이 아니거나, 본문 앞부분이 구글의 바이러스 검사 안내 페이지(`Google Drive - Virus scan warning` 포함)이면 그 페이지에서 `name="uuid" value="…"` 를 찾아 `https://drive.usercontent.google.com/download?id={id}&export=download&confirm=t&uuid={uuid}` 로 한 번 더 시도.
- 그래도 실패하면: 이전 games.json 에 같은 driveId 가 있으면 **기존 항목과 기존 파일을 그대로 유지**하고, 없으면 skipped 에 `내려받기 실패` 로 기록.
- 내용은 Buffer 로 다루고 **바이트 그대로** 저장한다(문자열 변환 후 저장 금지). 검사용으로만 utf8 문자열로 디코드.

## 3단계 — 해석 (파일마다)
1. 파일명 정규식 `/(\d{4})\s*([가-힣][가-힣\s]*[가-힣])\s*\.html$/i` → `studentNo`, `name`(모든 공백 제거). 불일치 → skipped, reason `파일명에서 학번·이름을 찾지 못함`.
2. 게임이 아닌 파일 → skipped:
   - 앞 2000자에 `saved from url=` 이 있고 `gemini.google.com` / `chatgpt.com` / `chat.openai.com` / `claude.ai` 중 하나가 있음 → reason `AI 대화 화면 저장본 (게임 파일 아님)`
   - `<title>` 내용이 ` - Google Gemini` 로 끝남 → 같은 reason
   - 크기 0 이거나 소문자화한 내용에 `<html` `<!doctype` `<script` `<canvas` `<body` 가 모두 없음 → reason `HTML 파일이 아님`
3. 제목: `/<title[^>]*>([\s\S]*?)<\/title>/i` 의 내용 → 엔티티 해제, 연속 공백을 한 칸으로, trim, 60자 초과면 59자 + `…`.
   비어 있으면 파일명에서 `.html`, 학번, 이름(공백 허용 형태), `code_artifact`, `index`, `(숫자)`, 앞뒤의 `-`·`_`·공백을 제거한 나머지. 그래도 비면 `{name}의 게임`.
4. `hash` = sha256(내용) 16진수 앞 16자, `size` = 바이트 수.

## 4단계 — ID 배정
이전 games.json 의 games 를 `prev` 라 한다. 이번에 유효한 파일 목록을 `cur` 라 한다(파일명 오름차순으로 정렬해 순서를 고정).
1. `cur` 중 `prev` 에 같은 `driveId` 가 있는 파일 → 그 `id`, `addedAt` 을 그대로 쓴다.
2. 나머지(새 파일)를 순서대로 처리:
   - 같은 `studentNo` 의 `prev` 항목 중 **그 driveId 가 이번 목록(cur 전체)에 없고, 아직 다른 새 파일이 이어받지 않은 것**이 있으면 → 그 `id` 와 `addedAt` 을 이어받는다(다시 제출). 후보가 여럿이면 id 가 가장 짧고 사전순으로 앞선 것.
   - 없으면 새 id: `studentNo` 가 이번 결과에서 아직 안 쓰였으면 `studentNo`, 쓰였으면 `studentNo-2`, `-3` … 중 안 쓰인 첫 번째. `addedAt` = 현재 시각.
   - "쓰였다"의 판단에는 1번에서 유지된 id 와 이어받은 id 를 모두 포함한다.
3. `updatedAt`: 이전 항목이 있고 hash 가 같으면 이전 `updatedAt`, 아니면 현재 시각.
4. overrides 적용: `overrides[id].title` 이 있으면 제목 교체. `overrides[id].hide === true` 이면 결과에서 빼고 skipped 에 reason `교사가 숨김` 으로 기록.

## 5단계 — 쓰기
- `play/{id}.html` 저장 (내용이 같으면 다시 쓰지 않음).
- `play/` 안의 `*.html` 중 이번 결과의 `{id}.html` 이 아니고 `index.html` 도 아닌 파일은 삭제.
- `site/games.json`:
  ```json
  { "updatedAt": "ISO", "games": [ {id, studentNo, name, title, file, driveId, sourceName, hash, size, addedAt, updatedAt} ], "skipped": [ {sourceName, driveId, reason} ] }
  ```
  - `file` = `{id}.html`. `games` 는 studentNo → id 오름차순, `skipped` 는 sourceName 오름차순.
  - **games 와 skipped 의 내용이 이전과 같으면 파일을 다시 쓰지 않는다** (최상위 `updatedAt` 만 달라지는 불필요한 커밋 방지). JSON 은 들여쓰기 2칸, 끝에 줄바꿈.
