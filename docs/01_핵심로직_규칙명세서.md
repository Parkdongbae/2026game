# 1. 핵심 로직·규칙 명세서

목적: 파일명 해석, 게임 ID, 좋아요 판정 기준을 한 가지로 통일한다. 화면·동기화 스크립트·Firestore 보안 규칙이 모두 이 문서를 따른다.

## 1. 제출 파일 해석

### 1.1 대상 파일

- 드라이브 제출 폴더 바로 아래에 있는 `.html` 파일만 대상이다. 하위 폴더와 다른 확장자는 무시한다.

### 1.2 파일명에서 학번·이름 추출

파일명 끝부분을 다음 정규식으로 읽는다.

```
/(\d{4})\s*([가-힣][가-힣\s]*[가-힣])\s*\.html$/
```

| 파일명 | 학번 | 이름 |
|---|---|---|
| `8_ball - 3115전예찬.html` | 3115 | 전예찬 |
| `code_artifact - 3108염 성 빈.html` | 3108 | 염성빈 (공백 제거) |
| `피카츄_8급한자_게임3102김민재.html` | 3102 | 김민재 |
| `code_artifact (1) - 2105박도윤.html` | 2105 | 박도윤 |

- 학번 4자리 = 학년(1) + 반(1) + 번호(2). `3115` → 3학년 1반 15번.
- 규칙에 맞지 않는 파일은 **게시하지 않고** 동기화 보고서의 "건너뜀"에 이유와 함께 적는다.

### 1.3 게임이 아닌 파일 걸러내기

다음 중 하나라도 해당하면 게시하지 않고 "건너뜀"에 적는다.

| 조건 | 이유 |
|---|---|
| 파일 앞 2,000자 안에 `saved from url=` 과 `gemini.google.com` / `chatgpt.com` / `claude.ai` 가 있음 | AI 대화 화면을 통째로 저장한 파일 (게임 코드가 아님) |
| `<title>` 이 ` - Google Gemini` 로 끝남 | 위와 같음 |
| 파일 크기 0 또는 `<html` / `<!doctype` / `<script` / `<canvas` / `<body` 중 아무것도 없음 | HTML이 아님 |

현재 해당 사례: `주술회전 철권 스타일 대전 게임 제작 - Google Gemini - 3109오예준.html` (Gemini 대화 페이지 저장본, 2.5MB).

### 1.4 게임 제목

1. `overrides.json` 에 제목이 있으면 그것
2. 파일 안 `<title>` 내용 (앞뒤 공백 제거, 60자 초과 시 자름)
3. 없으면 파일명에서 학번·이름·`code_artifact`·`index`·`(1)` 을 뺀 나머지
4. 그래도 비면 `{이름}의 게임`

## 2. 게임 ID

좋아요가 붙는 기준 키. **한 번 정해지면 바뀌지 않는다.**

- 형식: `학번` 또는 `학번-N` (N ≥ 2). 정규식 `^\d{4}(-\d+)?$`
- 배정 규칙 (`site/games.json` 에 기록된 `driveId` 로 판단):

| 상황 | 처리 |
|---|---|
| 이미 알고 있는 `driveId` | 기존 ID 유지 |
| 새 파일, 그 학번의 기존 게임이 없음 | ID = `학번` |
| 새 파일, 그 학번의 기존 파일이 폴더에서 **사라짐** | 다시 제출로 본다. 기존 ID를 **이어받는다** (좋아요 유지) |
| 새 파일, 그 학번의 기존 파일이 **그대로 있음** | 두 번째 작품으로 본다. ID = `학번-2`, `학번-3` … |
| 폴더에서 파일이 사라지고 대체 파일도 없음 | 갤러리에서 내린다. 좋아요 기록은 지우지 않는다 |

- 게임 파일의 주소는 `{게임주소}/{ID}.html` 이다.

### 2.1 한 학생이 여러 게임을 올리는 경우

- **허용한다. 개수 제한은 없다**(좋아요 보안 규칙상 한 학생당 99개까지). 게임마다 카드·좋아요가 따로 생긴다.
- 서로 다른 파일이면 올린 순서대로 `학번`, `학번-2`, `학번-3` … 이 붙는다. 처음 한꺼번에 여러 개를 올렸다면 파일 이름 순서로 붙는다.
- **내용이 완전히 같은 파일**을 같은 학생이 두 번 올리면 한 번만 게시한다(`sync-report.json` 에 "같은 파일을 두 번 올림"으로 기록, 갤러리 안내 상자에는 표시하지 않음).
- 여러 게임 중 하나를 고칠 때: 고칠 게임의 옛 파일을 지우고 새 파일을 올리면 그 게임의 ID와 좋아요를 이어받는다. 여러 개를 동시에 지우고 올리면 ID가 짧은 것부터 차례로 이어받는다.
- 검증(2026-11-24): 시험 파일로 `3115`, `3115-2`, `3115-3` 배정, 같은 파일 중복 제외, 교체 시 ID 유지 확인. 실제 폴더에서도 3311 학생의 게임 3개가 각각 올라감.

## 3. 좋아요 판정

### 3.1 누를 수 있는 사람

세 조건을 **모두** 만족해야 한다.

1. Firebase 구글 로그인 상태
2. 이메일이 `@dongshin.ms.kr` 로 끝남 (대소문자 무시, 하위 도메인 불가)
3. 이메일 인증됨 (`email_verified == true`)

검사는 두 곳에서 한다. 화면은 안내용이고, **Firestore 보안 규칙이 최종 판정**이다.

| 위치 | 동작 |
|---|---|
| 화면 | 다른 도메인으로 로그인하면 즉시 로그아웃시키고 "학교 계정만 가능" 안내 |
| 보안 규칙 | 조건 불충족 시 쓰기 거부 |

### 3.2 한 게임당 1개

- 좋아요 1개 = Firestore 문서 1개. 문서 ID를 `{게임ID}_{사용자uid}` 로 **강제**한다.
- 같은 사람이 같은 게임에 두 번째 문서를 만들 방법이 없으므로 중복이 구조적으로 불가능하다.
- 이미 누른 게임의 버튼을 다시 누르면 문서를 삭제한다(좋아요 취소).
- 한 사람이 좋아요할 수 있는 게임 수에는 제한이 없다.
- 자기 게임 좋아요: 막지 않는다 (계정과 학번을 연결하는 정보가 없음).

### 3.3 좋아요 수

- 게임별 수 = `likes` 컬렉션에서 `gameId == ID` 인 문서 수 (Firestore 집계 `count()`).
- 화면을 열 때 한 번 읽는다. 내가 누른 직후에는 화면에서 ±1 하고, 서버 저장이 실패하면 되돌린다.

### 3.4 보안 규칙이 강제하는 것

| 동작 | 허용 조건 |
|---|---|
| 읽기 | 누구나 |
| 만들기 | 3.1 충족 + 문서 ID == `gameId + '_' + uid` + `uid` 필드가 본인 + `gameId` 형식 일치 + 필드는 `gameId, uid, createdAt` 만 + `createdAt` 은 서버 시간 |
| 수정 | 불가 |
| 삭제 | 본인 문서만 |

## 4. 정렬·표시 규칙

| 항목 | 규칙 |
|---|---|
| 인기순 (기본) | 좋아요 많은 순 → 같으면 최신 등록 순 |
| 최신순 | `addedAt` 최근 순 |
| 학번순 | 학번 오름차순 |
| NEW | `addedAt` 이 72시간 이내 |
| 순위 메달 | 좋아요 1개 이상인 게임 중 상위 3개. 동점은 같은 순위 |
| 검색 | 제목·이름·학번에 입력 문자열이 포함 (공백·대소문자 무시) |

## 5. 동기화 규칙

1. 드라이브 폴더 목록(공개 링크)을 읽는다.
2. 모든 `.html` 을 내려받아 1장 규칙으로 해석한다.
3. 2장 규칙으로 ID를 정해 `play/{ID}.html` 로 저장한다. 내용은 **한 글자도 고치지 않는다.**
4. `site/games.json` 을 다시 쓴다. 새 게임만 `addedAt` 에 현재 시각을 넣고, 기존 게임은 유지한다. 내용(해시)이 바뀌면 `updatedAt` 만 갱신한다.
5. 바뀐 것이 있을 때만 커밋·푸시한다 → Vercel이 자동 배포한다.
6. 목록 읽기에 실패했거나 결과가 0개이면 **아무것도 지우지 않고 중단**한다 (일시 오류로 갤러리가 비는 사고 방지).

## 6. 게임 격리

| 항목 | 값 |
|---|---|
| 갤러리 | Vercel 프로젝트 A (`site/`) — 로그인·좋아요 |
| 게임 | Vercel 프로젝트 B (`play/`) — 학생 HTML 원본 |

- 두 주소는 서로 다른 출처(origin)라서 게임 안의 코드는 갤러리의 로그인 정보·Firestore 권한을 쓸 수 없다.
- 게임의 최고 기록 저장(localStorage)은 그대로 동작한다. 단, 모든 게임이 같은 저장 공간을 쓰므로 키 이름이 겹치면 서로 덮어쓸 수 있다 (현재 10개 중 6개가 사용).
- 갤러리의 게임 링크는 `target="_blank" rel="noopener noreferrer"` 로 연다.
